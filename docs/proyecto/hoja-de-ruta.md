# Hoja de ruta

Funcionalidades pendientes, por orden aproximado de prioridad. Las ideas salen en parte de la administración de ServiceSentry.

| # | Qué | Para qué | Notas |
|---|---|---|---|
| 8 | **Notificaciones** por email, Microsoft Teams o webhook | Avisar de eventos sin entrar en la web: secreto de Entra ID a punto de caducar, carpeta compartida que no existe, IP bloqueada, usuario desactivado, copia automática fallida | Configuración por canal y por tipo de evento; plantillas traducidas |
| 9 | **MFA (TOTP)** para usuarios locales | Segundo factor con una app de autenticación | Los usuarios de Entra ID ya tienen el MFA de Microsoft; códigos de recuperación y reinicio por un admin |
| 10 | **LDAP / Active Directory, SAML y SCIM** | LDAP para directorios locales; SAML para otros proveedores; SCIM para que Entra ID cree y desactive usuarios y grupos automáticamente | Hoy la revisión periódica (`auth.entra.directory_sync_minutes`) ya desactiva las cuentas con sesión o token que se borran o desactivan en Entra ID; SCIM lo haría al momento y crearía las cuentas y grupos antes del primer inicio de sesión. LDAP y SAML son un `AuthMethod` nuevo cada uno (ver *Extender StorageWeb*) |
| 12 | **Diagnóstico de dependencias** | Avisar de vulnerabilidades conocidas (CVE) en las bibliotecas instaladas | Consulta a una base de vulnerabilidades (OSV) desde *Sistema → Información* |
| 13 | **API de sincronización y cliente de Windows** | Sincronizar carpetas del equipo con StorageWeb al momento, como Dropbox: copia local completa, icono en la bandeja, inicio con Windows | Servidor: listado recursivo con versión (ETag/hash), **diario de cambios** con cursor («qué ha cambiado desde X») y escritura condicional (`If-Match`) para no pisar cambios ajenos. Cliente (Python empaquetado como `.exe`, en `clients/windows/`): inicio de sesión en el navegador que crea un token, elección de carpetas, vigilancia de cambios locales, base de datos local para saber quién cambió qué, conflictos como copia (`archivo (conflicto de PC-ANA).docx`), exclusión de temporales de Office, reanudación. Mientras tanto: unidad de red o `rclone bisync` ([Unidad de red](../uso/unidad-de-red.md)) |
| 14 | **Archivos a petición** (como OneDrive) | Los archivos aparecen en el Explorador sin ocupar espacio y se descargan al abrirlos, con iconos de estado | API *Cloud Files* de Windows (`CfRegisterSyncRoot`…): cliente en C#/.NET o C++. Usa la API de sincronización de la fila 13 |
| 16 | **Inicio de sesión con la cuenta de Windows en los clientes** | Que la extensión de VS Code y el cliente de Windows entren sin pasar por el navegador, con la sesión de Windows de un equipo unido a Entra ID (Intune), como OneDrive o Teams. Hoy la extensión ya puede **iniciar sesión en el navegador** (`/connect`, también con Entra ID) y recibir un token sin copiarlo | MSAL con el agente de cuentas de Windows (WAM) obtiene en silencio un token de acceso de Entra ID para la aplicación de StorageWeb; el servidor lo valida **con su firma** (claves JWKS del tenant, `aud`, `iss`, `tid`, caducidad) y lo acepta en lugar de un token propio. A diferencia del inicio de sesión web ([ADR 0004](../arquitectura/decisiones/0004-firma-id-token.md)), aquí el token llega del cliente, así que hay que verificar la firma |
| 17 | **Versiones de los archivos y papelera** | Recuperar la versión anterior de un archivo que se sobrescribió (guardar desde VS Code o la unidad de red, `COPY`/`MOVE` con sobrescritura) y deshacer un borrado; hoy borrar no tiene marcha atrás | Antes de sobrescribir o borrar, la versión actual se mueve a una carpeta interna de esa carpeta de StorageWeb (`.sw-versions/`, en el mismo almacenamiento: en disco un renombrado, en S3 una copia en el servidor), nunca listada ni accesible directamente; tabla con archivo, versión, tamaño, quién y cuándo. En la web, *Versiones* en cada archivo (ver, descargar, **restaurar**: la actual pasa a ser otra versión) y una papelera. Retención configurable (por ejemplo 10 versiones y 30 días) con limpieza como tarea de mantenimiento, y desactivable por carpeta. Lo delicado: que las versiones sigan al archivo al renombrar o mover, contar el espacio que ocupan (límites, Resumen, aviso), el coste en almacenamientos remotos (copia completa) y los permisos (los de descargar y subir en esa carpeta) |
| 18 | **Vista previa** de archivos | Ver imágenes, PDF, texto, vídeo y audio sin descargarlos | Solo tipos seguros y en un marco aislado (`sandbox`, CSP propia); nunca HTML ni SVG tal cual (podrían ejecutar código con la sesión del usuario). `Range` ya está para vídeo y audio. Miniaturas opcionales en la vista de lista |
| 19 | **Enlaces para compartir** con gente de fuera | Compartir un archivo o carpeta sin cuenta: enlace con caducidad, contraseña opcional, solo lectura o solo subida («buzón» para recibir archivos) | Toca seguridad: tokens largos, límites de descargas y de intentos de contraseña, auditoría de cada acceso, revocación desde *Mi perfil* y una página de administración con todos los enlaces activos. Opción global para desactivarlos |
| 20 | **Cuotas que bloquean** | Hoy las cuotas solo avisan (personales y compartidas, con el % usado); que además impidan subir al llegar al límite | Comprobar el espacio que queda en las subidas (web, por partes y WebDAV) y en copiar y mover; mensaje claro en cada cliente (la extensión de VS Code, la unidad de red); cuota por grupo; propiedades `quota-available-bytes` / `quota-used-bytes` de WebDAV (RFC 4331) para que el Explorador de Windows muestre el espacio de la unidad |
| 21 | **Antivirus en las subidas** | Analizar lo que se sube, sobre todo en carpetas compartidas o con enlaces públicos | ClamAV opcional (`clamd` por socket, `INSTREAM`); qué hacer con un positivo (rechazar o poner en cuarentena), aviso en el Resumen y auditoría |
| 22 | **Métricas para monitorización** | Ver la salud del servicio en Prometheus/Grafana o similar | `/metrics` (formato de Prometheus, con token o solo desde redes permitidas): peticiones y errores por ruta, subidas y descargas, espacio, inicios de sesión fallidos, IPs bloqueadas, estado de las ubicaciones remotas |
| 23 | **Restaurar una copia de seguridad desde la web** | Hoy se hace por la línea de comandos | Delicado: sustituye la base de datos con el servicio en marcha. Hacer antes una copia de lo actual, poner el servicio en mantenimiento, restaurar y reiniciar; solo administradores y con confirmación fuerte |

Si quieres trabajar en alguna, abre antes un issue (ver [Contribuir](contribuir.md)).
