# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

**Responde siempre en castellano**: respuestas, resúmenes, avisos entre herramientas, preguntas y la frase que presenta un bloque de código o un texto de commit. Sin excepciones, aunque sea una línea.

StorageWeb is a Flask + Waitress file server (upload/download) with local, PAM and Microsoft Entra ID (OAuth2/OIDC or MSAL) users, SQLite storage and a web admin. The project language is **Spanish**: docs (`docs/`, MkDocs), code comments, commit messages and the user conversation. UI/CLI source strings are **English** and translated to Spanish via gettext.

## Commands

On this Windows machine use the venv interpreter directly: `.venv/Scripts/python` (Linux/macOS: `.venv/bin/python`).

```bash
pip install -e ".[dev,docs]"                                   # setup
python -m storageweb --config config/config.dev.json serve --dev   # dev server, auto-reload, http://127.0.0.1:8080 (CLI: storageweb/cli/)
python -m storageweb --config config/config.dev.json user-add ana --role admin   # dev user

python -m pytest -q                                            # all tests (~6 min)
python -m pytest -q tests/unit                                 # fast subset
python -m pytest -q tests/integration/test_groups.py -k matrix # single file / test

python tools/i18n.py update      # re-extract strings into messages.pot and es/messages.po
python tools/i18n.py check       # fails on untranslated/obsolete strings (CI + test_i18n)
python tools/gen_docs.py         # regenerate docs/referencia/{configuracion,cli,api}.md
python tools/gen_docs.py --check
mkdocs build --strict
```

The pre-PR checklist (CONTRIBUTING.md) is: pytest, `gen_docs.py --check`, `i18n.py check`, `mkdocs build --strict`, plus an entry under *Sin publicar* in `CHANGELOG.md`. The same VS Code tasks exist in `.vscode/tasks.json`. Do not use Docker on this PC (it does not work here); `Dockerfile`/`compose.yaml` are only validated in CI.

## Architecture

Layering under `src/storageweb/` (enforced by review, see CONTRIBUTING.md): `web → core → db/providers → settings`. **Only `web/` imports Flask.** Repositories in `db/repositories/` are plain functions taking a `sqlite3.Connection` as first argument; business rules live in `core/`.

- **Settings** (ADR 0013): layers, field by field, lowest to highest: `DEFAULTS` < web settings (SQLite) < `config.json` < environment variables (`STORAGEWEB_<PATH>` with `__` between levels, `settings/env.py`, plus `ENV_ALIASES`). Loaded and validated by `settings/loader.py` (`normalize(file, path, overrides, env)`); merging/diffing by path in `settings/layers.py`; values in `settings/defaults.py`. **Every field is registered once in `settings/fields.py`** (`FIELDS`: `doc` for the generated reference, web `label`, admin `page`, search `words`; `label()`, `page_of()`, `display()`, `form_value()`). Sections editable from the web (`RUNTIME_SECTIONS`) are stored **one row per profile and field** in `settings_values` (ADR 0017, `settings/store.py`: `flatten`/`unflatten` — lists and `LEAF_PATHS` dicts are one field —, `read_doc`/`put_doc`; revision in `settings_profiles`) as the **minimal diff against the defaults** (`diff_overrides`), merged field by field (`merge_overrides`; dicts in `LEAF_PATHS`, e.g. `role_mappings`, are replaced whole). `RuntimeSettings.save(..., base=)` writes only the fields changed relative to the caller's snapshot, inside `BEGIN IMMEDIATE` (concurrent saves of different fields don't overwrite each other); every caller passes `base=runtime_view(settings())`. Tests use `tests/helpers.py` `stored_settings`/`store_settings`/`update_settings`, never raw SQL. The `settings` table is only internal state now. **Shares, locations and group quotas are entities, not settings** (ADR 0018): tables `shares`/`share_access`, `locations`/`location_options` (`db/repositories/catalog.py`, per profile) and `groups.home_quota_mb`. The effective cfg keeps the same shape (`cfg["storage"]["shares"|"locations"]` lists, `group_quotas` dict) with an `origin` on each item: `file`/`env` items come from config.json/env and are read-only per item (no whole-list lock: `locked()`/`origins()` skip `store.ENTITY_PATHS`; views use `access.entity_lock`), `web` items come from the tables. `loader.normalize` splits entity lists out of the web overrides and combines them with the config ones (config wins on name clashes). `RuntimeSettings.save` routes entity changes to `store.apply_entities` (by name, relative to `base`, location secrets encrypted) — callers keep saving full lists through `save_partial`. Tests write settings and entities with `tests/helpers.py` `store_settings` (also used by `make_app`). Fields set by config.json or the environment are **locked** (`RuntimeSettings.locked()/lock_of()`): forms disable them (`lock()` macro), `save()` drops them, and `save(strict=True)` (programmatic changes: matrix, folders, logo, Entra flows) raises. `RuntimeSettings.origins()` (web/file/env) drives the badges and `modified_paths()` the per-page counters; `reset_path` goes back to the default. Tests: `make_app` stores runtime sections in the DB; write config.json by hand to test locks. `ConfigError(message, field)` carries the dotted path so the page shows the error next to the field. `web/context.py` exposes `settings()`, `runtime()` and `get_db()` per request. The settings pages are the `web/views/settings/` package (one blueprint, one module per topic: `forms` — one page/form per section, `PARSERS` build the partial dict; `common.save_partial` merges and saves it; `branding`, `ips`, `sessions` — every admin session/token action, `backups`, `entra`) plus the Entra ID wizard, connection test (`providers/entra/check.py`) and one-click app registration via device code + Microsoft Graph (`providers/entra/register.py`; pending device flows live in a process-local dict, only a random key goes in the session). Changing a config field means updating defaults, `fields.py`, loader validation, the section parser/template and regenerating the reference docs.
- **Secrets at rest** (`settings/secretbox.py`): secret settings (`SECRET_FIELDS` + location `secret` options) are stored as `enc:v1:` AES-256-GCM in the `settings` table; `RuntimeSettings` encrypts on save and decrypts on read (`secrets_key`, set in `app.py` from `STORAGEWEB_SECRETS_KEY` or `<data_dir>/secrets.key`); plaintext values are still read as they are (a secret written in clear in config.json, or by tests); `enc:v1:` values in config.json/env are decrypted on load. Backups carry `secrets.key`; restores `rekey` to this server's key. CLI `encrypt-secret`, `rotate-secrets-key`.
- **Migrations**: `db/migrations/NNN_*.sql`, applied at app start with `PRAGMA user_version`; a migration that rebuilds a table starts with `-- foreign_keys: off`. Before the first production install the history was squashed into a single `001_initial.sql` (the whole current schema, commented); from now on **only add new numbered files and never edit one that any database may have applied** — the dev server applies new ones to `.dev/data/storageweb.db` immediately, so even unreleased migrations are frozen once the server ran. Every row needs its `uid` (users/groups): always insert through the repositories.
- **Auth** (ADR 0015): sign-in methods are **discovered**: each `providers/<method>/` defines an `AuthMethod` subclass (`providers/base.py`: `key`, `label`, capabilities `password`/`sso`/`stores_password`/`provisions`/`external_groups`, `verify` or `login_button`/`begin`/`complete`/`logout_url`, optional `notices`, `network_notes`, `directory`) with an `AuthConfig` (`settings/auth_methods.py`: defaults, `Field` docs, `validate`, secrets, leaf dicts) that is merged into `DEFAULTS["auth"]`, `FIELDS`, `SECRET_PATHS`/`LEAF_PATHS` on registration. `storageweb/__init__.py` is the composition root (imports `core` and `providers` before any config load). General code never names a method: `core/accounts.py` (`authenticate_password`, `login_sso`/`complete_sso` with an `Identity`, `resolve_role`, `sources()`, `source_labels()`, `stores_password()`), `core/groups.py` (`group_sources()`, `external_sources()`), routes `/auth/<method>/login|callback` (`auth.sso_login`/`auth.sso_callback`), login buttons, settings cards (`admin/settings/auth/<method>.html` or `_generic.html`, form readers in `web/views/settings/auth_forms.py`, Entra's in `entra.py`), the `auth_method()` Jinja global. Directory sync: `AuthMethod.sync_minutes`/`lookup_user` (→ `DirectoryUser`) feed the `directory_sync` maintenance task in `core/accounts.sync_directory`, which only checks accounts with a session or valid API token plus those it disabled (`users.disabled_reason = 'directory'`, re-enabled on their own; a manual enable/disable clears it). SSO accounts are keyed by source + external id: a new username at sign-in renames the account (`accounts.rename_account`, home via `storage.home_after_rename`, shares via the `on_rename` callback in `web/views/auth.py`). Front-channel logout: `/auth/<method>/frontchannel-logout` + `AuthMethod.frontchannel_session`, sessions carry `provider_sid` (the only page that allows framing, `guards.FRAMED_BY_PROVIDER`). `Identity.groups = None` means unknown (kept). Entra internals: `providers/entra/` (`method`, `sso` — `oauth2` default, stdlib-only, PKCE, no id_token signature check by design, ADR 0004 — and `msal`, `common`, `check`, `directory`, `register`). `users.source`/`groups.source` have no `CHECK` on the method list.
- **WebDAV** (`web/views/dav.py`, `/dav/`): network drive over the same roots/backends and permissions; auth only from the `Authorization` header (`guards._load_dav_user`: Basic user + API token, or the account password if `security.webdav_passwords`; Bearer), never the session cookie, so no CSRF; failures use their own `LoginThrottle` scope (`dav`) so a misconfigured drive never locks the web login, and an account password while not allowed is not counted; overwriting needs `upload` + `delete`; `COPY`/`MOVE` via `Backend.move`/`backends.copy_between`; fake LOCK; downloads go through `web/downloads.send_entry` (attachment + CSP sandbox). Errors in the `dav` blueprint are plain text (`web/errors.py`). PROPFIND always lists dot-files (`storage.show_hidden` is web-only: hiding them made sync clients think they were deleted).
- **VS Code extension** (`clients/vscode/`): plain JavaScript (`// @ts-check`), **no dependencies and never npm** (if ever needed, pnpm). VS Code-free modules (tested with Node): `src/sync.js` sync engine (3-way: local / server / last state, conflicts as copies, `If-Match`, loop check with a probe file — `SyncLoopError` —, `cancel()`, periodic state saves, server-hidden paths kept local), `src/dav.js` WebDAV client, `src/remotefs.js` files of a server as a file system, `src/servers.js` server profiles (`globalState` + tokens in `secrets`), `src/connect.js` browser sign-in (PKCE), `src/glob.js` excludes (defaults + `.storagewebignore`/`.gitignore` syntax). VS Code adapters: `src/provider.js` (`storageweb://<profile id>/<path>` FileSystemProvider; `watch()` registers open files/expanded folders and `poll()` — every `storageweb.refreshSeconds`, only with the window focused — compares a stat/listing signature and fires change events; own writes `rebase()` so they are not reported twice), `src/views.js` (activity-bar views *Servers* / *Synchronization*), `src/extension.js` (commands, pause state in `workspaceState`, watchers, URI handler). Texts via `vscode.l10n.t` + `l10n/bundle.l10n.es.json` and `package.nls*.json` (checked by `test/l10n.test.js` over all `src/*.js`). Tests: `node --test clients/vscode/test/*.test.js` (Node ≥ 18; Node 26 at `C:\Program Files\nodejs26\node.exe`); `test/extension.test.js` loads the extension with `test/vscode-mock.js` (every `package.json` command must be registered); `test/browser.js` is a fake browser for the `/connect` flow; `tests/integration/test_vscode_extension.py` runs them all against a live server (skipped without Node; asserts nothing is skipped). **Bump `package.json` version on every change you want installed**: VS Code does not reload a reinstalled same-version vsix. Package with `python tools/build_vsix.py [--install]`.
- **Connecting apps from the browser** (ADR 0016, `core/connect.py`, `web/views/connect.py`): OAuth with PKCE. `/connect/<client>` (login + CSRF form) issues a one-time 5-minute code kept in process memory and returns to a fixed per-client redirect (`CLIENTS`, e.g. `vscode://storageweb.storageweb-sync/auth`); `POST /connect/token` (CSRF-exempt via `guards.CONNECT_TOKEN_ENDPOINT`) redeems it with the verifier and only then creates the API token. Audit `app_authorized` + `api_token_created` (detail `connect`).
- **Self-registering extensions** (ADR 0015): Overview alerts `@alerts.source` (in the owning `core` module; `alerts.collect` imports all of `core` via `registry.import_submodules`), maintenance tasks `@maintenance.task`, CLI commands `@command` in `cli/common.py` (args declared by each command), search `search.action`/`@search.provider` in each web view module. Don't add central lists for these.
- **Groups** (`core/groups.py`, ADR 0011): tables `groups` + `user_groups` with `origin` = `manual`|`sync`. Logins only replace `sync` memberships of the user's source. `users.groups` is a denormalized **effective** list (`users.external_groups` from the IdP ∪ member group names) used by `core/storage.available_roots` for share access — always change memberships through `core/groups`, which calls `refresh_user`. The builtin `admins` group has no rows in `user_groups`: membership = `role == 'admin'`, added at request time in `available_roots`. Per-way read-only access is `storage.shares[].read_only_groups` / `read_only_users` (`*` allowed); `core/storage.share_access` grants write if **any** way the user enters allows it. Shared folders are edited per folder in `web/views/access.py` through `core/shares` (entries `{kind: all|user|group, ref, level}`) and by group in the access matrix (`core/groups.apply_access`).
- **Files**: `core/storage.py` (roots, listing, `explain_access`, `is_hidden`/`check_visible_name` for `storage.hidden` — gitignore-like patterns in `storageweb/patterns.py`, checked at every entry point: web `_rel`, chunk API, WebDAV `dav()` and COPY/MOVE destination, and filtered in `list_directory(hidden=…)`; WebDAV answers hidden paths with `X-StorageWeb-Hidden: 1`, the pattern list is never sent), `core/security.py` (`resolve_inside`, `safe_filename` — every user-supplied path/name must pass through them; on a Windows server, and always in SMB (`smb._unc`), and in SFTP/FTP/WebDAV locations with `windows_server` (schema `windows_option`; `Backend._clean` in each `_p`, flag set by `backends.backend_for`), `windows_reserved` rejects trailing dot/space, `:` (NTFS streams), wildcards and device names, and an 8.3 short name must be the real name — they bypassed `storage.hidden` or hung the request), `core/permissions.py` (role permissions; read-only roots only allow download). Multi-file operations in `core/files.py` (`transfer` move/copy across roots with WebDAV's permission rules and never overwriting, `zip_stream` streamed ZIP64 without temp files, `search` by name accent/case-insensitive with result/time/folder limits); web routes `/transfer`, `/roots`, `/zip`, `/search` in `web/views/files.py`, destination picker and drag & drop in `static/js/app.js`. Quotas (`core/quota.py`): `root["quota_mb"]` (home: `users.quota_mb` — NULL = groups (`storage.group_quotas`, largest, 0 wins) or `storage.home_quota_mb`, 0 = none —; shares: `storage.shares[].quota_mb`); with `storage.quota_enforce` **call `quota.check(root, cfg, incoming, freed)` before any write** (raises `QuotaExceeded`: web upload/transfer, chunk API init, WebDAV PUT/COPY/MOVE → `dav.InsufficientStorage` 507 with the reason) and `quota.record(root, delta)` after it (or `quota.invalidate` when the size is unknown: delete). Usage: measured by walking the backend, kept in memory with its time (`status()` → «Measured X ago»), adjusted by `record`; when older than `storage.quota_refresh_minutes` or marked stale by `invalidate`, it is re-measured in a background thread (`_schedule`, max 2 at once) while the old value is served — only the first measurement after start happens in the request (bounded); `quota.configure` is applied per request by `web/background.apply_process_settings`. Locations with `quota_exempt` give their roots `quota_mb = 0` (`storage.make_root`); WebDAV publishes RFC 4331 quota props only when asked. Free space: `Backend.space()` (local disk; S3/Azure `unlimited_space`) via `storage.space_of`; bars in `templates/_space.html` (width set by `common.js` from `data-percent`, CSP forbids `style=`). Large uploads use the resumable chunk API in `web/api/uploads.py` + `core/uploads.py` (`.sw-upload-<id>.part` files); downloads support Range.
- **Storage backends** (ADR 0014, `core/backends/`): every root dict carries a `backend` (`LocalBackend`, one per location type — `s3`, `smb`, `sftp`, `webdav`, `ftp`, `azure` — or `UnavailableBackend` carrying the error; remote reads with `seek` go through `base.RangedReader`) and all file operations take **relative POSIX paths** cleaned by `backends.clean_rel`; `root["path"]` is `None` for remote roots (use `backend.local_path()`). Location **types are discovered**: each `RemoteBackend` subclass in its own `core/backends/<type>.py` declares a `schema` (`settings/location_types.py`: `LocationSchema` + `Option`s with kind text/path/url/secret/bool/port) and implements `connect`/`create`/`address`; `backends.discover()` runs when `core` is imported and registers the schema in `settings.location_types`, which the loader (validation, `mask_secrets`), the generic admin form (`location_type()` Jinja global) and `gen_docs` read — never hard-code a type outside its module. Named connections are `storage.locations` (secret options blank in the form = keep), chosen by `shares[].location` and `storage.home_location` with a path relative to the location; admin page `web/views/locations.py` + `core/locations.py` (`describe`, `where`, `users_of`, `local_exists`, `test`). Chunked uploads stage the `.part` in `backend.staging_dir()` (next to the target on disk, `<data_dir>/uploads` for remote) and `store()` it on completion. `boto3`/`smbprotocol` are optional extras imported lazily; tests inject `tests/fakes.py` (`FakeS3`, `FakeSMB`) through `backends.CLIENT_FACTORIES` + `clear_clients()`.
- **Settings pages, one per topic** (`nav.py` + `forms.SECTIONS`/`PARSERS` + `admin/settings/<section>.html` + `Field.page`): Access → `storage` (personal folders), `quotas`; Security → `audit_settings` (retention, levels, SIEM); System → `general`, `network`, locations, `files` (hidden, max file size, large folders), `preview`, `auto_backups` (+ offsite), `backups` (op), `monitoring` (Prometheus), `system` (info). Each parser returns only its page's fields (unchecked boxes of other pages are never read). Never put a new setting in a page of another topic: add a page. Locked fields (config.json/env) are counted per page in the zone menu (`nav_locked`, lock pill) and listed at the top of the page (`admin/settings/_layout.html`).
- **Admin navigation** (`web/nav.py`): single registry of zones (People, Access, Security, System) and pages, each `config`/`op`/`info`; the rail, the zone subnav in `admin/_layout.html`, the Overview (`admin.index`; alerts come from `core/alerts.collect` via `context.admin_alerts()`, also used by the rail badge and the banner) and the Ctrl+K search (`web/search.py`, `admin.search`, `static/js/search.js`) are built from it. A new admin page needs a `Page` entry there. The `origin` macro leaves an anchor `#f-<path-with-dashes>` that search results link to.
- **Web**: `web/__init__.init_web` wires request hooks, `templating.py` (Jinja i18n, filters, common context), `errors.py` and `background.py` (maintenance tick); `app.py` only builds the config. Blueprints in `web/views/` (`auth`, `files`, `admin/` package — `overview`, `users`, `audit` —, `groups`, `access`, `profile`, `settings/` package); shared form helpers in `web/forms.py` (`split_list`, `checked`, `back`); external URLs (Entra redirect, logout) must use `context.external_url()`, which honours `network.public_url` and `web/api/`. `guards.py` provides session loading, locale selection, CSRF (form `_csrf` or `X-CSRF-Token` header), `admin_required`, `safe_next`. The CSP forbids inline scripts/styles: JS goes in `web/static/js/` (`common.js` on every page: `SW.t`, the app's own modal `SW.confirm`/`SW.prompt`/`SW.alert` (promises; never use the browser's `confirm`/`prompt`/`alert`), `form.js-confirm` with `data-confirm`, copy; `app.js` file browser; `search.js` Ctrl+K; `admin/forms.js` on every admin page — save bar with drafts, reset, tabs; `admin/{entra,matrix,bulk,user-form}.js` only on their pages via `{% block page_scripts %}`), data to JS via `<script type="application/json">`. CSS: `base.css` → `layout.css` → `files.css` → `admin.css`, loaded in that order.
- **Sessions, tokens, IP bans**: `start_session` registers a row in `sessions` and puts its id (`sid`) in the signed cookie; `load_current_user` rejects a cookie whose row is gone (closing a session = deleting the row). `Authorization: Bearer sw_…` authenticates with `core/tokens.py` (only the SHA-256 is stored), skips CSRF and is limited to the `files`/`uploads`/`health` blueprints; `tokens.restrict()` trims permissions to the token scope. `ip_gate` runs first; offenses go through `core/ipban.offense()` (loopback is never auto-banned). `core/maintenance.run_due()` (audit retention, cleanups, periodic backups) runs in a background thread every 10 min, never under `app.testing`.
- **Metrics** (`metrics.enabled`): `storageweb/metrics.py` (process counters, `metrics.inc`, Prometheus text format, no deps; `audit.log` counts every action), `core/monitoring.py` (scrape-time gauges from the DB/memory only — never walk folders or connect at scrape time; the `monitoring` maintenance task measures shares and tests locations), `web/views/metrics.py` (`/metrics`, token/allowed networks/loopback; skipped by `load_current_user`; also counts requests).
- **Restore from the web** (`core/maintenance.restore_backup`): `RESTORING` event → `guards.maintenance_gate` answers 503; safety backup (`label="antes-de-restaurar"`, not pruned: `backup.prune` only touches dated names), `backup.restore_online` (SQLite backup API into the live DB + migrations), all sessions deleted, in-memory caches cleared in `web/views/settings/backups.py`.
- **Public ids**: users and groups have a `uid` (UUID v4, set by `users.create`/`groups.create`) used in every admin URL and form (`/admin/users/<user_uid>`, `/admin/groups/<group_uid>`, `?u=`/`?g=`, bulk `ids`, `group_uid`, matrix field names); the integer `id` stays the internal key and is never accepted in URLs. Tests use `tests/helpers.py` `U(x)`/`G(x)` (row or id → uid).
- **Two-step verification** (`core/mfa/`: `totp.py` RFC 6238 and `qr.py` ISO 18004 written here, no deps; passkeys with `cbor.py`/`cose.py`/`webauthn.py` ported from ServiceSentry (no attestation check, alg fixed at registration, sign counter, RP ID/origin only from `network.public_url` via `mfa.passkey_scope` — name + HTTPS or localhost —, `security.passkeys`); service + policy in `__init__`; repo `db/repositories/mfa.py`, tables `mfa_factors`/`mfa_recovery`/`mfa_passkeys`, migrations 002 and 005). An account has the app, several named passkeys or both (`enrolled` = either); recovery codes belong to the account: generated with the first factor, dropped with the last (`disable` removes everything, `remove_totp`/`remove_passkey` only theirs). Web ceremonies are JSON (`web/views/mfa.py`, `static/js/passkeys.js`, forms in `templates/_passkeys.html`): one-use challenge in the signed cookie with purpose/user/expiry, also spent server-side (`mfa.spend_challenge`, process memory: an old cookie would bring it back, and platform authenticators keep no counter); the sign counter follows WebAuthn §7.2 step 21 (stored > 0 ⇒ the new one must be greater); the expected origin drops the default port; CBOR only in minimal form and authenticator data must end where its flags say (ED). Profile changes need a proof (`_proved`: code in the form or `mfa_proof` from `/profile/mfa/prove` or a passkey assertion, 5 min; failures count in the login `LoginThrottle` key, IP + account) — renaming a passkey too. Tests build ceremonies with `tests/webauthn_fabric.py`; the browser test uses a CDP virtual authenticator on `http://localhost`. only for password methods (`mfa.applies`: local, PAM), never SSO. `security.mfa_required` off/admins/all on the *Sign-in* settings page. A password sign-in that owes the code is **not a session**: `web/views/mfa.py` `hold()` leaves a signed `mfa_pending` note (5 min) and `/login/mfa` or `/login/mfa/enrol` (forced enrolment, never locks out) open the session after re-reading the account. Wrong codes go through the same `LoginThrottle` key as passwords and the correct password does not reset it while the code is pending. Codes are single-use (`last_step`, atomic `note_step`/`consume_recovery`). Seed encrypted with the secrets key; `secretbox.rekey` re-encrypts it. With MFA, WebDAV refuses the account password (tokens only). Admin reset in the user page, CLI `mfa-reset`/`mfa-status`.
- **Windows service** (ADR 0019): `storageweb service install|remove|start|stop|status` (`cli/service.py`, pure step builders tested anywhere) registers it with `sc.exe` under the virtual account `NT SERVICE\<name>` and grants it folders with `icacls`. The service runs the **base interpreter** (`sys._base_executable`, never the venv launcher) with `-S -I cli/service_boot.py --path <site-packages>`; `cli/service_host.py` talks to the SCM with `ctypes` (no pywin32) and stops Waitress via `trigger.pull_trigger` + `close_all` (`Runner`). HTTPS on Windows is Caddy (`packaging/caddy/Caddyfile`, shipped with the nginx/Apache templates; guide `docs/administracion/windows.md`); with Docker, `packaging/docker/compose.caddy.yaml` (Caddyfile inline in `configs`) or `packaging/docker/compose.traefik.yaml` (self-contained: published image `ghcr.io/vsc55/storageweb`, no `build`; the root `compose.yaml` is for development), both explained in `docs/administracion/docker.md`. The proxy examples on *Red y HTTPS* (nginx, Apache, Caddy, Traefik) come from `core/network.py` `example`. Never register a service on this PC.
- **File viewer** (`/view/<root>/<path>`, `files.view`, `templates/view.html`, `static/js/viewer.js`): `core/preview.py` decides what opens (`kind_of`: markdown/text/markup by extension or name), reads with a 2 MB limit (`read_text`: NUL → binary, UTF-8 else cp1252), log levels and previous/next. Markdown → HTML in `core/markdown.py`, **no deps and safe by construction**: every text is escaped and only its own tags come out; links/images go through the view's resolvers (`_md_link`/`_md_image`: http(s)/mailto, or a path inside the same root → viewer/download; external images and `javascript:`/`data:` → `None`); heading ids are prefixed `h-`. The view marks it `Markup` (the only place) and falls back to the source view if rendering ever raises. HTML/SVG are always shown as code. ```mermaid``` blocks become `.md-diagram` (code inside as fallback); `viewer.js` draws each one in an `<iframe sandbox=allow-scripts>` of `/diagram-frame` (`files.diagram_frame`: own CSP `sandbox allow-scripts`, explicit origin in `script-src`, `X-Frame-Options: SAMEORIGIN`, no session needed) via `postMessage` (frame says ready → gets the code → returns only its height). Mermaid is vendored in `static/vendor/mermaid/` by `tools/vendor.py` (pinned version + SHA-512, file SHA-256 checked by a test; never npm). `.gitattributes` keeps `static/vendor/**` byte-exact. The browser row has `data-href` (viewer or download), `data-view`, `data-download`. Audit: `download` with detail `view`. Settings `preview.*` (page *System → File preview*: `enabled` — off redirects `/view` to the download —, `diagrams` — off: no frame attribute and `/diagram-frame` 404s —, `max_mb` 1–20, `extensions` — the whole list, default `settings.defaults.PREVIEW_EXTENSIONS`; markdown/markup kinds come from `preview.MARKDOWN`/`MARKUP`, anything else is text —, `blocked_extensions` wins; names like README always open); `kind_of(name, options)` applies them (not in the list → `/view` redirects to the download) and the browser/search templates get `viewable(name)` from the view. Large texts (not Markdown) are shown by parts with `preview.read_window` (`?from=` byte offset, line-aligned, default the end).
- **Off-site backups** (`core/offsite.py`, `maintenance.offsite_location|path|keep`): `maintenance.send_offsite(conn, cfg, path, actor)` (cfg = effective settings, it needs `storage.locations`) copies the archive to the location through its backend (`ensure_root` + `store`), prunes dated ones there, stores `{at, ok, name, error}` under `offsite` in `maintenance_state` (alert `offsite_failed`) and audits. Called after the automatic task, the web *Create* button and the CLI `backup` (which reads the web settings with `settings.runtime.open_runtime`, the same opener `app.py` uses). The backups page lists the remote copies only with `?remote=1` (no connection on every visit); `offsite.fetch` downloads one into `<data_dir>/backups` after `check_restorable`.
- **Large folders** (`storage.page_size` 50–5000, `storage.listing_mode` scroll/pages/search): `files.browse` lists the whole folder but the HTML page only renders a slice (`files._listing`: `?page=`, `?q=` server-side name filter via `core/files.filter_by_name`); rows live in `templates/_file_rows.html`, also returned alone with `?rows=1` (headers `X-Total`, `X-Next`) for `app.js` (load more on scroll with an `IntersectionObserver`, server filter when `#listing-foot` exists; new rows are wired with `wireRow`/`wireRename`/`SW.confirmForm`). The JSON listing (API, VS Code, tokens) is never paginated.
- **Text editor** (`/edit/<root>/<path>`, `files.edit`, `templates/edit.html`, `static/js/editor.js`): permission `edit` (`permissions.user.edit`, off by default; dropped on read-only roots and read tokens), only whole UTF-8 texts the viewer opens (`_editable`). Optimistic concurrency with `downloads.etag` in a hidden `version` field: mismatch → 409, the user's text kept. Saved through a staging tmp + `backend.store` with `preview.encode_text` (keeps CRLF, final newline and BOM recorded by `read_text`), `quota.check(..., freed=old)`/`record(delta)`, audit `edit`. The `<textarea>` starts with a newline on purpose (the HTML parser drops one). Colors: `pre.editor-colors` under a transparent-text textarea (same font/padding, scroll synced, repainted on input; `.is-colored` only once painted so it degrades to plain text). One `.editor-box`: toolbar on top (language chip, icon buttons from `_icons.html`), text, line-number gutter (`.editor-gutter`, `--gutter` width set by JS, `.no-numbers` toggled from the status bar and kept in `localStorage`), status bar below (position, indent unit cycling 2/4/tab, `eol` hidden field LF/CRLF that `files.edit` honours). Toolbar (`data-cmd`) and shortcuts in `editor.js` edit through `execCommand("insertText")` so Ctrl+Z works; comment tokens per language come from `preview.COMMENTS`.
- **Code colors** (`preview.highlight`): highlight.js vendored in `static/vendor/highlight/` (common bundle + `preview.EXTRA_LANGUAGES` files), loaded only when needed; `preview.language_of(name)` (extension/name → hljs language), `HIGHLIGHT_MAX_BYTES` (viewer) / `EDITOR_HIGHLIGHT_MAX_BYTES`; `viewer.js` highlights the whole text and splits the HTML back into lines (re-opening spans), each wrapped in `.code-text` because lines are grid rows; palette `--hl-*` in `files.css`.
- **Favorites and recent** (`core/favorites.py`, repo `db/repositories/favorites.py`, migration 003): `favorites` rows per user (`root`, `rel`; `home` is each user's own, so `moved`/`deleted` only touch the actor's rows for it). Every rename/move/delete in `web/views/files.py` and WebDAV calls `favorites.moved`/`deleted`. Routes `files.favorite_toggle` (form or JSON; `action=remove` is the X of the sidebar list: removes without checking the target still exists) and `files.recent`; *Recent* is read from `audit_log` (web `download`/`upload`/`edit`, excluding WebDAV and token details).
- **Audit forwarding** (`storageweb/siem.py`, settings `audit.*` on *Security → Audit log*, section `audit_settings`): `db/repositories/audit.log` also calls `siem.emit`, which queues the event for a daemon thread (bounded queue, drops counted) that sends RFC 5424 syslog (udp/tcp lines/tls octet-counted; formats `rfc5424`/`json`/`cef`) and/or appends JSON lines to `audit.file`. The process-wide `siem.FORWARDER` is configured from the effective settings by `web/background.apply_process_settings` (before_request, cheap when unchanged) and by the CLI (`cli/__init__._forward_audit`, `flush()` at exit). Tests swap in a fresh `Forwarder` (autouse fixture in `tests/integration/test_siem.py`).
- **Audit**: everything a user or the system does calls `audit.log(...)` (web views: `guards.audit_event`, which also works without a session). Each event has a `level` (`storageweb/audit_levels.py`: `level_of(action, detail)` — put a new action in DEBUG/WARNING/ERROR/CRITICAL there if it is not `info` — and the doc row's *Nivel* column must match, enforced by `tests/unit/test_audit_levels.py`); `audit.min_level` (stored, applied per process with `audit_levels.configure`) and `audit.forward_min_level` (SIEM). 403s with a session are recorded centrally in `web/errors.py` (`access_denied`), CSRF failures in `guards.check_csrf`. WebDAV PROPFIND listings are deliberately not recorded (sync clients poll).
- **Audit docs**: every action name used in code must be listed in `docs/referencia/auditoria.md` (enforced by `tests/unit/test_docs.py`).

## i18n

- Wrap visible strings with `_()` / `ngettext` / `_l` (lazy, for module-level constants) from `storageweb.i18n`; Jinja uses the newstyle i18n extension (`_("…", name=x)`).
- JS strings must be registered in `web/js_messages.py` and used via `SW.t()` (from `common.js`) in the static JS.
- After adding strings: `tools/i18n.py update`, then fill the Spanish `msgstr` in `locale/es/LC_MESSAGES/messages.po` (compiled in memory, no `.mo`). Reusing an existing msgid reuses its translation (e.g. "Disabled" → "Deshabilitado").
- Web locale order: user preference > session > `Accept-Language` > `default_locale` (default `en`). CLI: `STORAGEWEB_LANG`/`LC_*`/`LANG`.

## Templates and tests: gotchas

- Browser tests: `tests/browser/*.test.mjs` (node:test + `tools/cdp.mjs`, the CDP driver shared with `tools/screenshots/capture.mjs`), run by `tests/integration/test_browser.py` against a live waitress server; every console error fails. `STORAGEWEB_REQUIRE_BROWSER=1` (CI on Linux) turns the skip into a failure. Add a scenario there when a feature lives mostly in JS.

- Macros imported with `{% from … import … %}` need `with context` to see `csrf_token`, `request` and context-processor variables.
- Never `{% set _ = … %}` in templates: it shadows gettext.
- Tests force Spanish (`tests/conftest.py`: autouse `spanish_locale`, config `"default_locale": "es"`), so assertions use Spanish text. Fixtures: `app`/`make_app(overrides)`, `client`, `logged` and `admin` (both return `(client, csrf_token)` and share the same `client` — use `app.test_client()` for a second session), `db_conn` for unit tests, `token_endpoint`/`entra_app` for SSO. Helpers in `tests/helpers.py` (`add_user`, `login`, `get_csrf`, `visible()` — strips the JS i18n catalog before negative text assertions).
