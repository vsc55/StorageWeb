# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

StorageWeb is a Flask + Waitress file server (upload/download) with local, PAM and Microsoft Entra ID (OAuth2/OIDC or MSAL) users, SQLite storage and a web admin. The project language is **Spanish**: docs (`docs/`, MkDocs), code comments, commit messages and the user conversation. UI/CLI source strings are **English** and translated to Spanish via gettext.

## Commands

On this Windows machine use the venv interpreter directly: `.venv/Scripts/python` (Linux/macOS: `.venv/bin/python`).

```bash
pip install -e ".[dev,docs]"                                   # setup
python -m storageweb --config config/config.dev.json serve --dev   # dev server, auto-reload, http://127.0.0.1:8080 (CLI: storageweb/cli/)
python -m storageweb --config config/config.dev.json user-add ana --role admin   # dev user

python -m pytest -q                                            # all tests (~6 min)
python -m pytest -q tests/unit                                 # fast subset
python -m pytest -q tests/integration/test_groups.py -k matrix # single file / test

python tools/i18n.py update      # re-extract strings into messages.pot and es/messages.po
python tools/i18n.py check       # fails on untranslated/obsolete strings (CI + test_i18n)
python tools/gen_docs.py         # regenerate docs/referencia/{configuracion,cli,api}.md
python tools/gen_docs.py --check
mkdocs build --strict
```

The pre-PR checklist (CONTRIBUTING.md) is: pytest, `gen_docs.py --check`, `i18n.py check`, `mkdocs build --strict`, plus an entry under *Sin publicar* in `CHANGELOG.md`. The same VS Code tasks exist in `.vscode/tasks.json`. Do not use Docker on this PC (it does not work here); `Dockerfile`/`compose.yaml` are only validated in CI.

## Architecture

Layering under `src/storageweb/` (enforced by review, see CONTRIBUTING.md): `web → core → db/providers → settings`. **Only `web/` imports Flask.** Repositories in `db/repositories/` are plain functions taking a `sqlite3.Connection` as first argument; business rules live in `core/`.

- **Settings** (ADR 0013): layers, field by field, lowest to highest: `DEFAULTS` < web settings (SQLite) < `config.json` < environment variables (`STORAGEWEB_<PATH>` with `__` between levels, `settings/env.py`, plus `ENV_ALIASES`). Loaded and validated by `settings/loader.py` (`normalize(file, path, overrides, env)`); merging/diffing by path in `settings/layers.py`; values in `settings/defaults.py`. **Every field is registered once in `settings/fields.py`** (`FIELDS`: `doc` for the generated reference, web `label`, admin `page`, search `words`; `label()`, `page_of()`, `display()`, `form_value()`). Sections editable from the web (`RUNTIME_SECTIONS`) are stored in the `settings` table under `runtime_key(settings_profile)` as the **minimal diff against the defaults** (`diff_overrides`), merged field by field (`merge_overrides`; dicts in `LEAF_PATHS`, e.g. `role_mappings`, are replaced whole). Fields set by config.json or the environment are **locked** (`RuntimeSettings.locked()/lock_of()`): forms disable them (`lock()` macro), `save()` drops them, and `save(strict=True)` (programmatic changes: matrix, folders, logo, Entra flows) raises. `RuntimeSettings.origins()` (web/file/env) drives the badges and `modified_paths()` the per-page counters; `reset_path` goes back to the default. Tests: `make_app` stores runtime sections in the DB; write config.json by hand to test locks. `ConfigError(message, field)` carries the dotted path so the page shows the error next to the field. `web/context.py` exposes `settings()`, `runtime()` and `get_db()` per request. The settings pages are the `web/views/settings/` package (one blueprint, one module per topic: `forms` — one page/form per section, `PARSERS` build the partial dict; `common.save_partial` merges and saves it; `branding`, `ips`, `sessions` — every admin session/token action, `backups`, `entra`) plus the Entra ID wizard, connection test (`providers/entra/check.py`) and one-click app registration via device code + Microsoft Graph (`providers/entra/register.py`; pending device flows live in a process-local dict, only a random key goes in the session). Changing a config field means updating defaults, `fields.py`, loader validation, the section parser/template and regenerating the reference docs.
- **Migrations**: `db/migrations/NNN_*.sql`, applied at app start with `PRAGMA user_version`; a migration that rebuilds a table starts with `-- foreign_keys: off` (see 007). **Never edit a migration once any database may have applied it** — the dev server applies new ones to `.dev/data/storageweb.db` immediately, so even unreleased migrations are frozen once the server ran. Add a new numbered file instead.
- **Auth** (ADR 0015): sign-in methods are **discovered**: each `providers/<method>/` defines an `AuthMethod` subclass (`providers/base.py`: `key`, `label`, capabilities `password`/`sso`/`stores_password`/`provisions`/`external_groups`, `verify` or `login_button`/`begin`/`complete`/`logout_url`, optional `notices`, `network_notes`, `directory`) with an `AuthConfig` (`settings/auth_methods.py`: defaults, `Field` docs, `validate`, secrets, leaf dicts) that is merged into `DEFAULTS["auth"]`, `FIELDS`, `SECRET_PATHS`/`LEAF_PATHS` on registration. `storageweb/__init__.py` is the composition root (imports `core` and `providers` before any config load). General code never names a method: `core/accounts.py` (`authenticate_password`, `login_sso`/`complete_sso` with an `Identity`, `resolve_role`, `sources()`, `source_labels()`, `stores_password()`), `core/groups.py` (`group_sources()`, `external_sources()`), routes `/auth/<method>/login|callback` (`auth.sso_login`/`auth.sso_callback`), login buttons, settings cards (`admin/settings/auth/<method>.html` or `_generic.html`, form readers in `web/views/settings/auth_forms.py`, Entra's in `entra.py`), the `auth_method()` Jinja global. Directory sync (migration 009): `AuthMethod.sync_minutes`/`lookup_user` (→ `DirectoryUser`) feed the `directory_sync` maintenance task in `core/accounts.sync_directory`, which only checks accounts with a session or valid API token plus those it disabled (`users.disabled_reason = 'directory'`, re-enabled on their own; a manual enable/disable clears it). SSO accounts are keyed by source + external id: a new username at sign-in renames the account (`accounts.rename_account`, home via `storage.home_after_rename`, shares via the `on_rename` callback in `web/views/auth.py`). Front-channel logout: `/auth/<method>/frontchannel-logout` + `AuthMethod.frontchannel_session`, sessions carry `provider_sid` (the only page that allows framing, `guards.FRAMED_BY_PROVIDER`). `Identity.groups = None` means unknown (kept). Entra internals: `providers/entra/` (`method`, `sso` — `oauth2` default, stdlib-only, PKCE, no id_token signature check by design, ADR 0004 — and `msal`, `common`, `check`, `directory`, `register`). Migration 007 dropped the `CHECK (source IN …)` on `users`/`groups`.
- **WebDAV** (`web/views/dav.py`, `/dav/`): network drive over the same roots/backends and permissions; auth only from the `Authorization` header (`guards._load_dav_user`: Basic user + API token, or the account password if `security.webdav_passwords`; Bearer), never the session cookie, so no CSRF; failures use their own `LoginThrottle` scope (`dav`) so a misconfigured drive never locks the web login, and an account password while not allowed is not counted; overwriting needs `upload` + `delete`; `COPY`/`MOVE` via `Backend.move`/`backends.copy_between`; fake LOCK; downloads go through `web/downloads.send_entry` (attachment + CSP sandbox). Errors in the `dav` blueprint are plain text (`web/errors.py`). PROPFIND always lists dot-files (`storage.show_hidden` is web-only: hiding them made sync clients think they were deleted).
- **VS Code extension** (`clients/vscode/`): plain JavaScript (`// @ts-check`), **no dependencies and never npm** (if ever needed, pnpm). VS Code-free modules (tested with Node): `src/sync.js` sync engine (3-way: local / server / last state, conflicts as copies, `If-Match`, loop check with a probe file — `SyncLoopError` —, `cancel()`, periodic state saves, server-hidden paths kept local), `src/dav.js` WebDAV client, `src/remotefs.js` files of a server as a file system, `src/servers.js` server profiles (`globalState` + tokens in `secrets`), `src/connect.js` browser sign-in (PKCE), `src/glob.js` excludes (defaults + `.storagewebignore`/`.gitignore` syntax). VS Code adapters: `src/provider.js` (`storageweb://<profile id>/<path>` FileSystemProvider), `src/views.js` (activity-bar views *Servers* / *Synchronization*), `src/extension.js` (commands, pause state in `workspaceState`, watchers, URI handler). Texts via `vscode.l10n.t` + `l10n/bundle.l10n.es.json` and `package.nls*.json` (checked by `test/l10n.test.js` over all `src/*.js`). Tests: `node --test clients/vscode/test` (Node ≥ 18; Node 26 at `C:\Program Files\nodejs26\node.exe`); `test/extension.test.js` loads the extension with `test/vscode-mock.js` (every `package.json` command must be registered); `test/browser.js` is a fake browser for the `/connect` flow; `tests/integration/test_vscode_extension.py` runs them all against a live server (skipped without Node; asserts nothing is skipped). **Bump `package.json` version on every change you want installed**: VS Code does not reload a reinstalled same-version vsix. Package with `python tools/build_vsix.py [--install]`.
- **Connecting apps from the browser** (ADR 0016, `core/connect.py`, `web/views/connect.py`): OAuth with PKCE. `/connect/<client>` (login + CSRF form) issues a one-time 5-minute code kept in process memory and returns to a fixed per-client redirect (`CLIENTS`, e.g. `vscode://storageweb.storageweb-sync/auth`); `POST /connect/token` (CSRF-exempt via `guards.CONNECT_TOKEN_ENDPOINT`) redeems it with the verifier and only then creates the API token. Audit `app_authorized` + `api_token_created` (detail `connect`).
- **Self-registering extensions** (ADR 0015): Overview alerts `@alerts.source` (in the owning `core` module; `alerts.collect` imports all of `core` via `registry.import_submodules`), maintenance tasks `@maintenance.task`, CLI commands `@command` in `cli/common.py` (args declared by each command), search `search.action`/`@search.provider` in each web view module. Don't add central lists for these.
- **Groups** (`core/groups.py`, ADR 0011): tables `groups` + `user_groups` with `origin` = `manual`|`sync`. Logins only replace `sync` memberships of the user's source. `users.groups` is a denormalized **effective** list (`users.external_groups` from the IdP ∪ member group names) used by `core/storage.available_roots` for share access — always change memberships through `core/groups`, which calls `refresh_user`. The builtin `admins` group has no rows in `user_groups`: membership = `role == 'admin'`, added at request time in `available_roots`. Per-way read-only access is `storage.shares[].read_only_groups` / `read_only_users` (`*` allowed); `core/storage.share_access` grants write if **any** way the user enters allows it. Shared folders are edited per folder in `web/views/access.py` through `core/shares` (entries `{kind: all|user|group, ref, level}`) and by group in the access matrix (`core/groups.apply_access`).
- **Files**: `core/storage.py` (roots, listing, `explain_access`, `is_hidden`/`check_visible_name` for `storage.hidden` — gitignore-like patterns in `storageweb/patterns.py`, checked at every entry point: web `_rel`, chunk API, WebDAV `dav()` and COPY/MOVE destination, and filtered in `list_directory(hidden=…)`; WebDAV answers hidden paths with `X-StorageWeb-Hidden: 1`, the pattern list is never sent), `core/security.py` (`resolve_inside`, `safe_filename` — every user-supplied path/name must pass through them), `core/permissions.py` (role permissions; read-only roots only allow download). Multi-file operations in `core/files.py` (`transfer` move/copy across roots with WebDAV's permission rules and never overwriting, `zip_stream` streamed ZIP64 without temp files, `search` by name accent/case-insensitive with result/time/folder limits); web routes `/transfer`, `/roots`, `/zip`, `/search` in `web/views/files.py`, destination picker and drag & drop in `static/js/app.js`. Quotas only warn (`core/quota.py`): `root["quota_mb"]` (home: `users.quota_mb` — migration 008, NULL = `storage.home_quota_mb`, 0 = none —; shares: `storage.shares[].quota_mb`); usage summed over the backend and cached 10 min, **call `quota.invalidate(root)` after any write** (web upload/delete/transfer, chunk API complete, WebDAV PUT/DELETE/COPY/MOVE). Free space: `Backend.space()` (local disk; S3/Azure `unlimited_space`) via `storage.space_of`; bars in `templates/_space.html` (width set by `common.js` from `data-percent`, CSP forbids `style=`). Large uploads use the resumable chunk API in `web/api/uploads.py` + `core/uploads.py` (`.sw-upload-<id>.part` files); downloads support Range.
- **Storage backends** (ADR 0014, `core/backends/`): every root dict carries a `backend` (`LocalBackend`, one per location type — `s3`, `smb`, `sftp`, `webdav`, `ftp`, `azure` — or `UnavailableBackend` carrying the error; remote reads with `seek` go through `base.RangedReader`) and all file operations take **relative POSIX paths** cleaned by `backends.clean_rel`; `root["path"]` is `None` for remote roots (use `backend.local_path()`). Location **types are discovered**: each `RemoteBackend` subclass in its own `core/backends/<type>.py` declares a `schema` (`settings/location_types.py`: `LocationSchema` + `Option`s with kind text/path/url/secret/bool/port) and implements `connect`/`create`/`address`; `backends.discover()` runs when `core` is imported and registers the schema in `settings.location_types`, which the loader (validation, `mask_secrets`), the generic admin form (`location_type()` Jinja global) and `gen_docs` read — never hard-code a type outside its module. Named connections are `storage.locations` (secret options blank in the form = keep), chosen by `shares[].location` and `storage.home_location` with a path relative to the location; admin page `web/views/locations.py` + `core/locations.py` (`describe`, `where`, `users_of`, `local_exists`, `test`). Chunked uploads stage the `.part` in `backend.staging_dir()` (next to the target on disk, `<data_dir>/uploads` for remote) and `store()` it on completion. `boto3`/`smbprotocol` are optional extras imported lazily; tests inject `tests/fakes.py` (`FakeS3`, `FakeSMB`) through `backends.CLIENT_FACTORIES` + `clear_clients()`.
- **Admin navigation** (`web/nav.py`): single registry of zones (People, Access, Security, System) and pages, each `config`/`op`/`info`; the rail, the zone subnav in `admin/_layout.html`, the Overview (`admin.index`; alerts come from `core/alerts.collect` via `context.admin_alerts()`, also used by the rail badge and the banner) and the Ctrl+K search (`web/search.py`, `admin.search`, `static/js/search.js`) are built from it. A new admin page needs a `Page` entry there. The `origin` macro leaves an anchor `#f-<path-with-dashes>` that search results link to.
- **Web**: `web/__init__.init_web` wires request hooks, `templating.py` (Jinja i18n, filters, common context), `errors.py` and `background.py` (maintenance tick); `app.py` only builds the config. Blueprints in `web/views/` (`auth`, `files`, `admin/` package — `overview`, `users`, `audit` —, `groups`, `access`, `profile`, `settings/` package); shared form helpers in `web/forms.py` (`split_list`, `checked`, `back`); external URLs (Entra redirect, logout) must use `context.external_url()`, which honours `network.public_url` and `web/api/`. `guards.py` provides session loading, locale selection, CSRF (form `_csrf` or `X-CSRF-Token` header), `admin_required`, `safe_next`. The CSP forbids inline scripts/styles: JS goes in `web/static/js/` (`common.js` on every page: `SW.t`, the app's own modal `SW.confirm`/`SW.prompt`/`SW.alert` (promises; never use the browser's `confirm`/`prompt`/`alert`), `form.js-confirm` with `data-confirm`, copy; `app.js` file browser; `search.js` Ctrl+K; `admin/forms.js` on every admin page — save bar with drafts, reset, tabs; `admin/{entra,matrix,bulk,user-form}.js` only on their pages via `{% block page_scripts %}`), data to JS via `<script type="application/json">`. CSS: `base.css` → `layout.css` → `files.css` → `admin.css`, loaded in that order.
- **Sessions, tokens, IP bans** (migration 006): `start_session` registers a row in `sessions` and puts its id (`sid`) in the signed cookie; `load_current_user` rejects a cookie whose row is gone (closing a session = deleting the row). `Authorization: Bearer sw_…` authenticates with `core/tokens.py` (only the SHA-256 is stored), skips CSRF and is limited to the `files`/`uploads`/`health` blueprints; `tokens.restrict()` trims permissions to the token scope. `ip_gate` runs first; offenses go through `core/ipban.offense()` (loopback is never auto-banned). `core/maintenance.run_due()` (audit retention, cleanups, periodic backups) runs in a background thread every 10 min, never under `app.testing`.
- **Audit**: relevant actions call `audit.log(...)`. Every action name used in code must be listed in `docs/referencia/auditoria.md` (enforced by `tests/unit/test_docs.py`).

## i18n

- Wrap visible strings with `_()` / `ngettext` / `_l` (lazy, for module-level constants) from `storageweb.i18n`; Jinja uses the newstyle i18n extension (`_("…", name=x)`).
- JS strings must be registered in `web/js_messages.py` and used via `SW.t()` (from `common.js`) in the static JS.
- After adding strings: `tools/i18n.py update`, then fill the Spanish `msgstr` in `locale/es/LC_MESSAGES/messages.po` (compiled in memory, no `.mo`). Reusing an existing msgid reuses its translation (e.g. "Disabled" → "Deshabilitado").
- Web locale order: user preference > session > `Accept-Language` > `default_locale` (default `en`). CLI: `STORAGEWEB_LANG`/`LC_*`/`LANG`.

## Templates and tests: gotchas

- Macros imported with `{% from … import … %}` need `with context` to see `csrf_token`, `request` and context-processor variables.
- Never `{% set _ = … %}` in templates: it shadows gettext.
- Tests force Spanish (`tests/conftest.py`: autouse `spanish_locale`, config `"default_locale": "es"`), so assertions use Spanish text. Fixtures: `app`/`make_app(overrides)`, `client`, `logged` and `admin` (both return `(client, csrf_token)` and share the same `client` — use `app.test_client()` for a second session), `db_conn` for unit tests, `token_endpoint`/`entra_app` for SSO. Helpers in `tests/helpers.py` (`add_user`, `login`, `get_csrf`, `visible()` — strips the JS i18n catalog before negative text assertions).
