# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

**Responde siempre en castellano**: respuestas, resúmenes, avisos entre herramientas, preguntas y la frase que presenta un bloque de código o un texto de commit. Sin excepciones, aunque sea una línea.

StorageWeb is a Flask + Waitress file server (upload/download) with local, PAM and Microsoft Entra ID (OAuth2/OIDC or MSAL) users, SQLite storage and a web admin. The project language is **Spanish**: docs (`docs/`, MkDocs), code comments, commit messages and the user conversation. UI/CLI source strings are **English** and translated to Spanish via gettext.

## Commands

On this Windows machine use the venv interpreter directly: `.venv/Scripts/python` (Linux/macOS: `.venv/bin/python`).

```bash
pip install -e ".[dev,docs]"                                   # setup
python -m storageweb --config config/config.dev.json serve --dev   # dev server, auto-reload, http://127.0.0.1:8080 (CLI: storageweb/cli/)
python -m storageweb --config config/config.dev.json user-add ana --role admin   # dev user

python -m pytest -q                                            # all tests (~6 min)
python -m pytest -q tests/unit                                 # fast subset
python -m pytest -q tests/integration/test_groups.py -k matrix # single file / test

python tools/i18n.py update      # re-extract strings into messages.pot and es/messages.po
python tools/i18n.py check       # fails on untranslated/obsolete strings (CI + test_i18n)
python tools/gen_docs.py         # regenerate docs/referencia/{configuracion,cli,api}.md
python tools/gen_docs.py --check
mkdocs build --strict
```

The pre-PR checklist (CONTRIBUTING.md) is: pytest, `gen_docs.py --check`, `i18n.py check`, `mkdocs build --strict`, plus an entry under *Sin publicar* in `CHANGELOG.md`. The same VS Code tasks exist in `.vscode/tasks.json`. Do not use Docker on this PC (it does not work here); `Dockerfile`/`compose.yaml` are only validated in CI.

## Architecture

Layering under `src/storageweb/` (enforced by review, see CONTRIBUTING.md): `web → core → db/providers → settings`. **Only `web/` imports Flask.** Repositories in `db/repositories/` are plain functions taking a `sqlite3.Connection` as first argument (partial updates through `db/connection.update_row(conn, table, id, fields, allowed)`); business rules live in `core/`.

- **Settings** (ADR 0013): layers, field by field, lowest to highest: `DEFAULTS` < web settings (SQLite) < `config.json` < environment variables (`STORAGEWEB_<PATH>` with `__` between levels, `settings/env.py`, plus `ENV_ALIASES`). Loaded and validated by `settings/loader.py` (`normalize(file, path, overrides, env)`); merging/diffing by path in `settings/layers.py`; values in `settings/defaults.py`. **Every field is registered once in `settings/fields.py`** (`FIELDS`: `doc` for the generated reference, web `label`, admin `page`, search `words`; `label()`, `page_of()`, `display()`, `form_value()`). Sections editable from the web (`RUNTIME_SECTIONS`) are stored **one row per profile and field** in `settings_values` (ADR 0017, `settings/store.py`: `flatten`/`unflatten` — lists and `LEAF_PATHS` dicts are one field —, `read_doc`/`put_doc`; revision in `settings_profiles`) as the **minimal diff against the defaults** (`diff_overrides`), merged field by field (`merge_overrides`; dicts in `LEAF_PATHS`, e.g. `role_mappings`, are replaced whole). `RuntimeSettings.save(..., base=)` writes only the fields changed relative to the caller's snapshot, inside `BEGIN IMMEDIATE` (concurrent saves of different fields don't overwrite each other); every caller passes `base=runtime_view(settings())`. Tests use `tests/helpers.py` `stored_settings`/`store_settings`/`update_settings`, never raw SQL. The `settings` table is only internal state now. **Shares, locations and group quotas are entities, not settings** (ADR 0018): tables `shares`/`share_access`, `locations`/`location_options` (`db/repositories/catalog.py`, per profile) and `groups.home_quota_mb`. The effective cfg keeps the same shape (`cfg["storage"]["shares"|"locations"]` lists, `group_quotas` dict) with an `origin` on each item: `file`/`env` items come from config.json/env and are read-only per item (no whole-list lock: `locked()`/`origins()` skip `store.ENTITY_PATHS`; views use `access.entity_lock`), `web` items come from the tables. `loader.normalize` splits entity lists out of the web overrides and combines them with the config ones (config wins on name clashes). `RuntimeSettings.save` routes entity changes to `store.apply_entities` (by name, relative to `base`, location secrets encrypted) — callers keep saving full lists through `save_partial`. Tests write settings and entities with `tests/helpers.py` `store_settings` (also used by `make_app`). Fields set by config.json or the environment are **locked** (`RuntimeSettings.locked()/lock_of()`): forms disable them (`lock()` macro), `save()` drops them, and `save(strict=True)` (programmatic changes: matrix, folders, logo, Entra flows) raises. `RuntimeSettings.origins()` (web/file/env) drives the badges and `modified_paths()` the per-page counters; `reset_path` goes back to the default. Tests: `make_app` stores runtime sections in the DB; write config.json by hand to test locks. `ConfigError(message, field)` carries the dotted path so the page shows the error next to the field. `web/context.py` exposes `settings()`, `runtime()` and `get_db()` per request. The settings pages are the `web/views/settings/` package (one blueprint, one module per topic: `forms` — one page/form per section, `PARSERS` build the partial dict; `common.save_partial` merges and saves it; `branding`, `ips`, `sessions` — every admin session/token action, `backups`, `entra`) plus the Entra ID wizard, connection test (`providers/entra/check.py`) and one-click app registration via device code + Microsoft Graph (`providers/entra/register.py`; pending device flows live in a process-local dict, only a random key goes in the session). Changing a config field means updating defaults, `fields.py`, loader validation, the section parser/template and regenerating the reference docs.
- **Secrets at rest** (`settings/secretbox.py`): secret settings (`SECRET_FIELDS` + location `secret` options) are stored as `enc:v1:` AES-256-GCM in the `settings` table; `RuntimeSettings` encrypts on save and decrypts on read (`secrets_key`, set in `app.py` from `STORAGEWEB_SECRETS_KEY` or `<data_dir>/secrets.key`); plaintext values are still read as they are (a secret written in clear in config.json, or by tests); `enc:v1:` values in config.json/env are decrypted on load. Backups carry `secrets.key`; restores `rekey` to this server's key. CLI `encrypt-secret`, `rotate-secrets-key`.
- **Migrations**: `db/migrations/NNN_*.sql`, applied at app start with `PRAGMA user_version`; a migration that rebuilds a table starts with `-- foreign_keys: off`. Before the first production install the history was squashed into a single `001_initial.sql` (the whole current schema, commented); from now on **only add new numbered files and never edit one that any database may have applied** — the dev server applies new ones to `.dev/data/storageweb.db` immediately, so even unreleased migrations are frozen once the server ran. Every row needs its `uid` (users/groups): always insert through the repositories.
- **Auth** (ADR 0015): sign-in methods are **discovered**: each `providers/<method>/` defines an `AuthMethod` subclass (`providers/base.py`: `key`, `label`, capabilities `password`/`sso`/`stores_password`/`provisions`/`external_groups`, `verify` or `login_button`/`begin`/`complete`/`logout_url`, optional `notices`, `network_notes`, `directory`) with an `AuthConfig` (`settings/auth_methods.py`: defaults, `Field` docs, `validate`, secrets, leaf dicts) that is merged into `DEFAULTS["auth"]`, `FIELDS`, `SECRET_PATHS`/`LEAF_PATHS` on registration. `storageweb/__init__.py` is the composition root (imports `core` and `providers` before any config load). General code never names a method: `core/accounts.py` (`authenticate_password`, `login_sso`/`complete_sso` with an `Identity`, `resolve_role`, `sources()`, `source_labels()`, `stores_password()`), `core/groups.py` (`group_sources()`, `external_sources()`), routes `/auth/<method>/login|callback` (`auth.sso_login`/`auth.sso_callback`), login buttons, settings cards (`admin/settings/auth/<method>.html` or `_generic.html`, form readers in `web/views/settings/auth_forms.py`, Entra's in `entra.py`), the `auth_method()` Jinja global. Directory import (People → Users → Import from …, `admin.user_import`): `AuthMethod.can_import`/`search_people`/`list_people` (pages; the cursor is validated, Entra rebuilds the Graph URL from `$skiptoken` only)/`get_person`/`import_notice` (→ `DirectoryPerson` with `warning`, e.g. not assigned when the enterprise app requires assignment: `directory.assignment` = directly assigned users + direct members of assigned groups, needs `Application.Read.All`; username computed with the same rules as sign-in, e.g. Entra `person_from_graph`/`username_from`) live search/bulk in `static/js/admin/directory-import.js`) feed `core/accounts.import_methods`/`import_account` (re-reads the person by id, links a hand-made account without external id, refuses name clashes and `allowed_groups` misses). Directory sync: `AuthMethod.sync_minutes`/`lookup_user` (→ `DirectoryUser`) feed the `directory_sync` maintenance task in `core/accounts.sync_directory`, which only checks accounts with a session or valid API token plus those it disabled (`users.disabled_reason = 'directory'`, re-enabled on their own; a manual enable/disable clears it). SSO accounts are keyed by source + external id: a new username at sign-in renames the account (`accounts.rename_account`, home via `storage.home_after_rename`, shares via the `on_rename` callback in `web/views/auth.py`). Front-channel logout: `/auth/<method>/frontchannel-logout` + `AuthMethod.frontchannel_session`, sessions carry `provider_sid` (the only page that allows framing, `guards.FRAMED_BY_PROVIDER`). `Identity.groups = None` means unknown (kept). Entra internals: `providers/entra/` (`method`, `sso` — `oauth2` default, stdlib-only, PKCE, no id_token signature check by design, ADR 0004 — and `msal`, `common`, `check`, `directory`, `register`). `users.source`/`groups.source` have no `CHECK` on the method list.
- **WebDAV** (`web/views/dav.py`, `/dav/`): network drive over the same roots/backends and permissions; auth only from the `Authorization` header (`guards._load_dav_user`: Basic user + API token, or the account password if `security.webdav_passwords`; Bearer), never the session cookie, so no CSRF; failures use their own `LoginThrottle` scope (`dav`) so a misconfigured drive never locks the web login, and an account password while not allowed is not counted; overwriting needs `upload` + `delete`; `COPY`/`MOVE` via `Backend.move`/`backends.copy_between`; fake LOCK; downloads go through `web/downloads.send_entry` (attachment + CSP sandbox). Errors in the `dav` blueprint are plain text (`web/errors.py`). PROPFIND always lists dot-files (`storage.show_hidden` is web-only: hiding them made sync clients think they were deleted).
- **VS Code extension** (`clients/vscode/`): plain JavaScript (`// @ts-check`), **no dependencies and never npm** (if ever needed, pnpm). VS Code-free modules (tested with Node): `src/sync.js` sync engine (3-way: local / server / last state, conflicts as copies, `If-Match`, loop check with a probe file — `SyncLoopError` —, `cancel()`, periodic state saves, server-hidden paths kept local), `src/dav.js` WebDAV client, `src/remotefs.js` files of a server as a file system, `src/servers.js` server profiles (`globalState` + tokens in `secrets`), `src/connect.js` browser sign-in (PKCE), `src/glob.js` excludes (defaults + `.storagewebignore`/`.gitignore` syntax). VS Code adapters: `src/provider.js` (`storageweb://<profile id>/<path>` FileSystemProvider; `watch()` registers open files/expanded folders and `poll()` — every `storageweb.refreshSeconds`, only with the window focused — compares a stat/listing signature and fires change events; own writes `rebase()` so they are not reported twice), `src/views.js` (activity-bar views *Servers* / *Synchronization*), `src/extension.js` (commands, pause state in `workspaceState`, watchers, URI handler). Texts via `vscode.l10n.t` + `l10n/bundle.l10n.es.json` and `package.nls*.json` (checked by `test/l10n.test.js` over all `src/*.js`). Tests: `node --test clients/vscode/test/*.test.js` (Node ≥ 18; Node 26 at `C:\Program Files\nodejs26\node.exe`); `test/extension.test.js` loads the extension with `test/vscode-mock.js` (every `package.json` command must be registered); `test/browser.js` is a fake browser for the `/connect` flow; `tests/integration/test_vscode_extension.py` runs them all against a live server (skipped without Node; asserts nothing is skipped). **Bump `package.json` version on every change you want installed**: VS Code does not reload a reinstalled same-version vsix. Package with `python tools/build_vsix.py [--install]`.
- **Connecting apps from the browser** (ADR 0016, `core/connect.py`, `web/views/connect.py`): OAuth with PKCE. `/connect/<client>` (login + CSRF form) issues a one-time 5-minute code kept in process memory and returns to a fixed per-client redirect (`CLIENTS`, e.g. `vscode://storageweb.storageweb-sync/auth`); `POST /connect/token` (CSRF-exempt via `guards.CONNECT_TOKEN_ENDPOINT`) redeems it with the verifier and only then creates the API token. Audit `app_authorized` + `api_token_created` (detail `connect`). **Windows account** (no browser): `/connect/desktop` — `GET` lists the methods whose `AuthMethod.desktop(section)` returns `{provider, tenant, scopes}`, `POST {method, client, access_token, device}` checks it with `AuthMethod.desktop_identity` (Entra: `providers/entra/access_token.verify` — signature first, RS256 against the JWKS (`?appid=`) of the configured tenant or `common`, never the token's `tid`, and the key's own `issuer`; cached a day, refetched on an unknown kid at most every 5 min, one fetch at a time (5 s timeout), a failure or an empty key set not retried for 60 s → 503, not audited; v2 only (`ver` 2.0, `aud` = client id), `iss`, `tid` as a GUID (`_tenant_allowed`: `organizations` without the consumer tenant, `consumers` not offered), `exp`/`nbf`, `scp` `access_as_user`, `azp` VS Code; only an unsigned/forged token counts for `ipban` — then `identity_from_claims`, refusing a missing `username_claim` and keeping the stored email), signs in with `accounts.login_sso(reenable=False)` (a directory-disabled account is not re-enabled from an up-to-1-h-old token) and returns `connect.desktop_token` (90 days); the extension accepts only `microsoft` + exactly `api://<GUID>/access_as_user` + a tenant-shaped tenant, only over https/loopback, and pins it per server (`WINDOWS_PINS`; *Sign in again* goes straight to Windows only when pinned); CSRF-exempt (`guards.CONNECT_ENDPOINTS`). Setting `auth.entra.desktop_sign_in`; `register.expose_desktop_api` (identifier URI, scope, VS Code pre-authorized) runs on registration and in *Repair permissions*. Tests sign real tokens with `tests/entra_keys.py`.
- **Self-registering extensions** (ADR 0015): Overview alerts `@alerts.source` (in the owning `core` module; `alerts.collect` imports all of `core` via `registry.import_submodules`), maintenance tasks `@maintenance.task`, CLI commands `@command` in `cli/common.py` (args declared by each command), search `search.action`/`@search.provider` in each web view module. Don't add central lists for these.
- **Groups** (`core/groups.py`, ADR 0011): tables `groups` + `user_groups` with `origin` = `manual`|`sync`. Logins only replace `sync` memberships of the user's source. `users.groups` is a denormalized **effective** list (`users.external_groups` from the IdP ∪ member group names) used by `core/storage.available_roots` for share access — always change memberships through `core/groups`, which calls `refresh_user`. The builtin `admins` group has no rows in `user_groups`: membership = `role == 'admin'`, added at request time in `available_roots`. Per-way read-only access is `storage.shares[].read_only_groups` / `read_only_users` (`*` allowed); `core/storage.share_access` grants write if **any** way the user enters allows it. Shared folders are edited per folder in `web/views/access.py` through `core/shares` (entries `{kind: all|user|group, ref, level}`) and by group in the access matrix (`core/groups.apply_access`).
  Groups can be **disabled** (`groups.enabled`, migration 010, `group_core.set_enabled`): kept whole but `refresh_user` drops them (name and external id, `repo.disabled_refs`) from `users.groups`, so they give no shares/role/quota even if the provider sends them; the builtin `admins` never. **Clone** = `groups.new?copy=<uid>` (`group_core.clone_group`, always local, members as manual — also from `admins` —; role, quota and share access are copied by the view). **Import** from a provider's directory: `groups.import_view` (`GroupDirectory.search`/`list`, Entra `directory.search_groups`/`list_groups` — `None` = could not read —, registered with `register_external`), same page/JS as people import (`static/js/admin/directory-import.js`). Avatars: `group_avatar` (rounded square, `group_initials`); disabled people and groups show a grey avatar with `#i-ban` (`avatar-off`/`avatar-ban`), never a struck name.
- **Roles** (`core/roles.py`, repo `db/repositories/roles.py`, migrations 007/009): built-in `admin` (everything), `user` (`permissions.user` setting, edited in its record `roles.edit key=user` with config locks) and `none` («No permissions», the default `permissions.default_role`; deleting a custom role moves its people to `none`) plus custom roles (table `roles`: key slug, label, description, permissions). Assigned to a person (`users.role`, no fixed CHECK any more) and to a group (`groups.role`, `group_core.set_role` — never `admin`). `permissions.permissions_for(user, cfg)` = union of `role_permissions` over `roles_of(user, cfg)` (own role + group roles via `users.groups`), still pure: `RuntimeSettings.current` injects `cfg["roles"]`/`cfg["group_roles"]` from `settings.store.read_roles`, and every change calls `store.roles_changed` (revision `state:roles`, read together with the settings revision). An unknown role counts as `user`. `permissions.default_role` (`permissions.default_role(cfg)`) is the role of new accounts (web, CLI, import, SSO when the method's `default_role` is empty). Templates use the `role_label(key)`/`role_choices(admin=True)` globals (never `ROLE_LABELS[...]` on a user's role). Page *Access → Roles* (`web/views/roles.py`, nav key still `permissions`, no settings section any more): views `roles.list_view`/`roles.panel_view` like users/groups (`roles_view` in the session, `roles.index` redirects; new/edit/delete go back to it), `roles.make_default` (the star macro `default_star`, any role incl. admin — confirmed in the page, posture check `default_role` warns), `roles.new/edit/delete` (`roles.new?copy=<key>` = Clone, prefilled by `roles.copy_of`; keys `new`/`list`/`panel` reserved; the panel's tabs `general`/`permissions`/`members` post only their `part`, Save button in the head via `form="role-tab-form"`); accounts/CLI validate with `roles.exists`; config.json role_mappings accept any key-shaped value, the web only existing roles.
- **Files**: `core/storage.py` (roots, listing, `explain_access`, `is_hidden`/`check_visible_name` for `storage.hidden` — gitignore-like patterns in `storageweb/patterns.py`, checked at every entry point: web `_rel`, chunk API, WebDAV `dav()` and COPY/MOVE destination, and filtered in `list_directory(hidden=…)`; WebDAV answers hidden paths with `X-StorageWeb-Hidden: 1`, the pattern list is never sent), `core/security.py` (`resolve_inside`, `safe_filename` — every user-supplied path/name must pass through them; on a Windows server, and always in SMB (`smb._unc`), and in SFTP/FTP/WebDAV locations with `windows_server` (schema `windows_option`; `Backend._clean` in each `_p`, flag set by `backends.backend_for`), `windows_reserved` rejects trailing dot/space, `:` (NTFS streams), wildcards and device names, and an 8.3 short name must be the real name — they bypassed `storage.hidden` or hung the request), `core/permissions.py` (role permissions; read-only roots only allow download). Multi-file operations in `core/files.py` (`transfer` move/copy across roots with WebDAV's permission rules and never overwriting, `zip_stream` streamed ZIP64 without temp files, `search` by name accent/case-insensitive with result/time/folder limits); web routes `/transfer`, `/roots`, `/zip`, `/search` in `web/views/files.py`, destination picker and drag & drop in `static/js/files/transfer.js`. Quotas (`core/quota.py`): `root["quota_mb"]` (home: `users.quota_mb` — NULL = groups (`storage.group_quotas`, largest, 0 wins) or `storage.home_quota_mb`, 0 = none —; shares: `storage.shares[].quota_mb`); with `storage.quota_enforce` **call `quota.check(root, cfg, incoming, freed)` before any write** (raises `QuotaExceeded`: web upload/transfer, chunk API init, WebDAV PUT/COPY/MOVE → `dav.InsufficientStorage` 507 with the reason) and `quota.record(root, delta)` after it (or `quota.invalidate` when the size is unknown: delete). Usage: measured by walking the backend, kept in memory with its time (`status()` → «Measured X ago»), adjusted by `record`; when older than `storage.quota_refresh_minutes` or marked stale by `invalidate`, it is re-measured in a background thread (`_schedule`, max 2 at once) while the old value is served — only the first measurement after start happens in the request (bounded); `quota.configure` is applied per request by `web/background.apply_process_settings`. Locations with `quota_exempt` give their roots `quota_mb = 0` (`storage.make_root`); WebDAV publishes RFC 4331 quota props only when asked. Free space: `Backend.space()` (local disk; S3/Azure `unlimited_space`) via `storage.space_of`; bars in `templates/_space.html` (width set by `common.js` from `data-percent`, CSP forbids `style=`). Large uploads use the resumable chunk API in `web/api/uploads.py` + `core/uploads.py` (`.sw-upload-<id>.part` files); downloads support Range.
- **Allowed server folders** (`storage.allowed_folders`, page *System → Server folders*, `settings/server_paths.py`: `real` — realpath, never for network paths —, `base_of`, `allowed_path`, `permitted` — also refuses network paths unless inside an allowed folder, even with an empty list —): disk shares and `home_template` are checked by the loader, own `users.home_path` by `accounts.check_home_path` (create/update with `cfg=`, CLI via `cli/common.effective`), `storage.make_root` gives a disk root outside them an `UnavailableBackend`, `pathpicker.browse_disk(allowed=)` lists only inside; `storage.disk_folders` feeds the page's in-use table; `audit.file` too (`loader._check_audit_file`: inside them, never in `data_dir` or the config.json, a network path only inside an allowed folder). Empty = anywhere.
- **Storage backends** (ADR 0014, `core/backends/`): every root dict carries a `backend` (`LocalBackend`, one per location type — `s3`, `smb`, `sftp`, `webdav`, `ftp`, `azure` — or `UnavailableBackend` carrying the error; remote reads with `seek` go through `base.RangedReader`; S3 and Azure share `objects.ObjectStoreBackend` — prefixes, ranged open, mkdir marker, move, delete, store, root, check — and only implement their service calls `_read_from`/`_put_empty`/`_keys_under`/`_move_object`/`_delete_keys`/`_upload`/`_any_under`/`_fail` plus `stat`/`listdir`) and all file operations take **relative POSIX paths** cleaned by `backends.clean_rel`; `root["path"]` is `None` for remote roots (use `backend.local_path()`). Location **types are discovered**: each `RemoteBackend` subclass in its own `core/backends/<type>.py` declares a `schema` (`settings/location_types.py`: `LocationSchema` + `Option`s with kind text/path/server_path/url/secret/multiline/bool/port/seconds) and implements `connect`/`create`/`address`; `backends.discover()` runs when `core` is imported and registers the schema in `settings.location_types`, which the loader (validation, `mask_secrets`), the generic admin form (`location_type()` Jinja global) and `gen_docs` read — never hard-code a type outside its module. Named connections are `storage.locations` (secret options blank in the form = keep), chosen by `shares[].location` and `storage.home_location` with a path relative to the location; admin page `web/views/locations.py` + `core/locations.py` (`describe`, `where`, `users_of`, `local_exists`, `test`). Temporary upload files are always `backend.staging_file(dir_rel)` (or `backends.temp_name()` outside a backend). Form uploads (file browser, share-link drop box) go through `core/files.receive(cfg, root, rel, filename, save, max_bytes)` → `(final, size)` or `UploadRefused` (`reason` name/too_large/quota/write). ## i18n

- Wrap visible strings with `_()` / `ngettext` / `_l` (lazy, for module-level constants) from `storageweb.i18n`; Jinja uses the newstyle i18n extension (`_("…", name=x)`).
- JS strings must be registered in `web/js_messages.py` and used via `SW.t()` (from `common.js`) in the static JS.
- After adding strings: `tools/i18n.py update`, then fill the Spanish `msgstr` in `locale/es/LC_MESSAGES/messages.po` (compiled in memory, no `.mo`). Reusing an existing msgid reuses its translation (e.g. "Disabled" → "Deshabilitado").
- Web locale order: user preference > session > `Accept-Language` > `default_locale` (default `en`). CLI: `STORAGEWEB_LANG`/`LC_*`/`LANG`.

## Templates and tests: gotchas

- Browser tests: `tests/browser/*.test.mjs` (node:test + `tools/cdp.mjs`, the CDP driver shared with `tools/screenshots/capture.mjs`), run by `tests/integration/test_browser.py` against a live waitress server; every console error fails. `STORAGEWEB_REQUIRE_BROWSER=1` (CI on Linux) turns the skip into a failure. The page language comes from `Emulation.setUserAgentOverride`/`setLocaleOverride` in `cdp.launch` (`--lang` only works on Windows), and CI's headless browser reports `hover: none`: don't assume a mouse. Add a scenario there when a feature lives mostly in JS.

- Error and status pages (`error.html`, `link_gone.html`) extend `_status_frame.html` (login frame without a session, centred in the app with one) and are rendered through `web/errors.error_page(code, name, description)` (titles, icons and «what you can do» tips per code). Pages without a session never show the app version (no public footer; `/healthz` has no version).
- List filters that must survive F5/navigation use `web/forms.remembered(arg, session_key, allowed, default)`; the List/Panels view of users, groups and roles is `forms.use_view(key, view)`/`last_view(key)`. Their header and search are the macros of `admin/_panels.html` (`view_switch`, `page_head`, `search_form` with `{% call %}` for the section's buttons/selects), wrapped by each section's `_macros.html`.
- Accent/case-insensitive matching and slugs: `storageweb/text.py` (`fold`, `slug`), used by core and web — don't write another NFKD helper.

- Macros imported with `{% from … import … %}` need `with context` to see `csrf_token`, `request` and context-processor variables.
- Never `{% set _ = … %}` in templates: it shadows gettext.
- Tests force Spanish (`tests/conftest.py`: autouse `spanish_locale`, config `"default_locale": "es"`), so assertions use Spanish text. Fixtures: `app`/`make_app(overrides)`, `client`, `logged` and `admin` (both return `(client, csrf_token)` and share the same `client` — use `app.test_client()` for a second session), `db_conn` for unit tests, `token_endpoint`/`entra_app` for SSO. Helpers in `tests/helpers.py` (`add_user`, `login`, `get_csrf`, `visible()` — strips the JS i18n catalog before negative text assertions).
